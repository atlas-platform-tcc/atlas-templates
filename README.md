# atlas-templates

Templates for services generated by the Atlas Golden Path.

- **`go-service-template/`** — the application scaffold. Atlas copies and parametrizes it to create
  a new service repository (Go app + `Dockerfile` + CI). Two GitHub workflows: `ci.yml` builds and
  pushes an immutable image on every push to `main` (no deploy); `deploy.yml` is a manual
  (`workflow_dispatch`) day-2 promotion — the developer's "Run workflow" click is the gate. Keeping
  them separate means a push never shows a confusing "skipped" deploy job. It also carries
  `deploy/values.yaml`, the only file a developer edits to tune the runtime (replicas, env).
- **`charts/base/`** — the shared base Helm chart, referenced centrally (not copied per service).
  It renders the Kubernetes manifests and enforces the platform guardrails: readiness/liveness
  probes, resource requests/limits, required labels and a non-root security context.

Per-service desired state (values) lives in `atlas-gitops`, not in the chart.

## Stack

- Go 1.26
- Helm

## Run (reference service)

```bash
docker build -t hello-service:dev go-service-template
docker run --rm -p 8080:8080 hello-service:dev
curl -s http://localhost:8080/healthz   # -> ok
```

## Test (chart)

```bash
helm lint charts/base
helm template hello charts/base
```
